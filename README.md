# Gift Tracker — Telegram-бот

Рабочий проект на Node.js 24. Для чтения маркета используются @mtcute/node и long (версии закреплены в package-lock.json). SQLite встроен в Node.js. Проверенная среда: Node.js 24.21.0. Исходники находятся в `src/`, схема и начальная миграция — `migrations/001.sql` (автоматически применяется при открытии БД).

## Что реализовано

Главное меню, два одноразовых теста, обычный/VIP доступ, ключи и промокоды, персональные ссылки с заявками, проверка подписки на канал, удаление по истечении доступа, Stars-счета, защита от повторного начисления платежа, публикация по ценовым диапазонам, атомарная бронь и личная карточка. Одна публикация на лот; копии в нескольких темах намеренно не включены. Уровни, Premium и стоимость сообщения выводятся только если их предоставил источник.

После брони публичные поля и превью скрываются, кнопка показывает занявшего пользователя. В личные сообщения поступает карточка по приложенному образцу: Gift, Price, Model, Message, Status, продавец, ссылка на подарок, «Открыть профиль» и «Скопировать». «Оффер (-2%)» появляется только при наличии `offerUrl` от адаптера. Сам бот не отправляет оффер и не покупает подарок. Вместо вводящего в заблуждение Thanks for buying используется «Лот закреплён за вами».

Изображение подарка показывается через превью исходной ссылки, если Telegram создаёт такое превью. Это позволяет убрать его вместе с карточкой через editMessageText. Цвета кнопок, их форма и внешний вид встроенного превью управляются клиентом Telegram; точное пиксельное совпадение не гарантируется. `imageUrl` хранится, но отдельно в группу не отправляется.

## Источник и ограничения

Новые объявления собираются с Telegram-маркета через подключённую пользовательскую MTProto-сессию. Перед публикацией лот сверяется в see.tg по точному slug; карточка публикуется только после получения публичного username. Подробности мониторинга и настройки сессии — в [MARKET.md](MARKET.md). SOURCE=telegram используется по умолчанию; SOURCE=demo оставлен для тестов.

### Лента see.tg

Основной сбор объявлений выполняет модуль Telegram-маркета через сессию пользователя. См. [MARKET.md](MARKET.md) для ограничений обхода коллекций и Telegram flood-wait. Гостевая лента `wss://live.see.tg/v1/ws` может быть включена отдельно через `SEE_FEED_ENABLED=true` для событий see.tg; она не заменяет сканер Telegram.

Гостевые события see.tg могут скрывать владельца. Бот не использует замаскированное имя как контакт и публикует найденное объявление только после точной сверки slug и получения username. Бесплатная проверка использует публичную страницу подарка и, если настроен токен и бесплатный лимит доступен, документированный GET `/v1/gift/{slug}` после проверки `/v1/me`. При исчерпанном/неизвестном лимите запрос подарка не выполняется; платные `/who` и платные вызовы не используются. Если ни один бесплатный источник не показывает профиль, лот остаётся в очереди.

Перед публикацией бот бесплатно проверяет публичную страницу `https://t.me/nft/<slug>` и, при доступной бесплатной квоте API, точный объект see.tg по тому же slug. Лоты без подтверждённого username остаются в очереди и проверяются повторно. Платные методы `/who` и поиск аккаунта по имени не используются. Если Telegram/see.tg показывают только имя или скрывают профиль, бесплатно достоверно восстановить username из ID/имени нельзя; такой лот не публикуется.

## Запуск на Windows

1. Установите Node.js 24 (проверено на 24.21.0).
2. Создайте бота через @BotFather. Создайте закрытую супергруппу и включите темы.
3. Назначьте бота администратором с правами приглашения, блокировки участников и удаления сообщений. Разрешите отправку сообщений и ссылок. Для обязательного канала бот также должен быть администратором.
4. Скопируйте настройки:

```powershell
Copy-Item .env.example .env
```

5. Заполните `BOT_TOKEN`. Чтобы узнать ID, запустите:

```powershell
node --env-file=.env src/setup.js
```

Напишите `/ids` в личные сообщения бота и в каждую тему группы. Утилита выводит `user_id`, `chat_id`, `thread_id`. Запишите свой user_id в `ADMIN_IDS`, ID группы в `GROUP_ID`, thread_id в соответствующие `topics` файла `config.json`. Остановите утилиту Ctrl+C. Она потребляет обновления: использовать только до запуска основного бота, не во время работы/продаж. Если бот ранее использовал webhook, сначала удалите его штатным deleteWebhook; проект использует polling.

6. Укажите контакт поддержки в `SUPPORT_TEXT`. Несколько администраторов в `ADMIN_IDS` перечисляются через запятую. `REQUIRED_CHANNEL_ID` оставьте пустым, если обязательной подписки нет.
7. Все включённые темы должны иметь действующий threadId. Неиспользуемым темам поставьте `enabled:false`. Настройте цены и длительности в config.json.
8. Запустите:

```powershell
npm test
npm run demo
npm start
```

До запуска выполните install.bat или npm ci. Для SOURCE=telegram также выполните вход через login-market.bat по инструкции MARKET.md. `npm run demo` работает без токена и печатает образцы карточек, резервируя тестовый лот в памяти. `npm start` подключается к Telegram и требует настоящих настроек. Не кладите токен в код, Git или скриншоты.

## VIP и темы

Внутри одной группы Telegram нельзя скрыть отдельные темы от пользователей обычного тарифа. В режиме одной группы VIP-проверка блокирует занятие VIP-лота, но не его просмотр. Для закрытого просмотра задайте `VIP_GROUP_ID` отдельной приватной супергруппы. ID VIP-тем должны относиться к ней. VIP получает ссылку в VIP-группу; обычный тариф — в основную. Стандартные лоты в этом режиме остаются в основной группе, автоматически в VIP-группу не копируются.

Приватные ссылки принимают заявки, а сервер сверяет ссылку, владельца, чат и срок доступа. Пересланная ссылка другого пользователя не допускает. Само вступление в обязательный канал не выдаёт подписку. Исключение после окончания доступа выполняется в рабочем цикле бота; если бот выключен, удаление произойдёт после запуска. Бот контролирует участников, принятых через его заявки: перед эксплуатацией уберите посторонних участников и иные приглашения. Администраторов группы бот исключать не может.

## Админ-панель

Откройте /admin или кнопку ⚙️ Админ-панель. Подключение аккаунта по номеру и коду, выдача VIP и другие действия описаны в [ADMIN.md](ADMIN.md). Вход выполняется в локальной форме без QR.

## Управление

Администратор сначала пишет боту /start. Команды отправляются в личные сообщения; права проверяются по ADMIN_IDS.

```text
/admin
/admin grant USER_ID standard 1440
/admin grant USER_ID vip 1440
/admin revoke USER_ID
/admin code vip 60 24 10
/admin pause
/admin resume
/admin reload
/admin stats
/admin refund USER_ID TELEGRAM_PAYMENT_CHARGE_ID
```

`grant` выдаёт/продлевает доступ в минутах. Пользователь обязан предварительно начать диалог. `code` создаёт код: тариф, минуты доступа, часы действия кода, максимум активаций. Один человек активирует код один раз; код хранится как SHA-256. Действующий VIP нельзя заменить обычным тарифом. Повышение с standard до VIP переносит оставшееся время на VIP; учитывайте это при выборе тарифов.

Тексты главного меню, сроки тестов, тарифы, кулдауны, названия/ID тем, валюта и диапазоны меняются в config.json. Шаблоны карточек и остальные тексты — src/cards.js и src/service.js. `/admin reload` проверяет и загружает config.json без перезапуска. Фильтр выбирает первую подходящую тему: min включительно, max исключительно. Для TON добавьте отдельные диапазоны currency=TON. Тема «100%» отключена, пока не задан реальный критерий.

`/admin stats` показывает ошибки очереди. Платёжные ошибки входящих обновлений находятся в `inbox.error` SQLite. `/terms` и `/paysupport` возвращают SUPPORT_TEXT: до продаж укажите там понятные условия доступа, контакт и порядок возврата. Оплата — разовая в XTR (Stars), автоматического списания нет. Доступ начисляется только по successful_payment с совпадающими пользователем, суммой и заказом. Снимок тарифа сохраняется в заказе. Возврат через `/admin refund` отзывает весь текущий доступ пользователя; применять осознанно.

## Данные и восстановление

Транзакция BEGIN IMMEDIATE сохраняет бронь и задания hide/deliver вместе; второй клиент не может перехватить бронь. Повторная ошибка Telegram не освобождает лот. Задания повторяются с экспоненциальной задержкой до часа с учётом retry_after. Входящие обновления и offset записываются до обработки. Платёж с уже учтённым charge не продлевает доступ повторно.

Запускайте один процесс на одну БД/токен. От второго экземпляра защищает блокировка SQLite в файле *.process-lock.sqlite. При аварийном завершении процесса система освобождает её автоматически; удалять файл не требуется. Старый пустой .lock больше не используется. Перед первым запуском обновлённой версии закройте прежние окна бота. Не удаляйте *.process-lock.sqlite во время работы процесса. Скопируйте БД для резервного хранения при остановленном боте; при копировании работающей БД необходимо учитывать WAL и SHM.

Telegram не предоставляет ключ идемпотентности для sendMessage. При обрыве после отправки, но до сохранения ответа, повторная отправка может создать дубль сообщения. Резерв и начисление платежа остаются однократными на уровне БД. Это ограничение внешней доставки, а не гарантия exactly-once. Высокая нагрузка потребует отдельного планировщика лимитов Telegram; текущая очередь обрабатывает 429 с retry_after. Не используйте демонстрационную конфигурацию как высоконагруженную торговую систему.

## Проверка

Автоматические тесты проверяют конкуренцию двух независимых SQLite-соединений, одноразовые тесты, истечение доступа, ключи, повторные платежи после перезапуска, устойчивую очередь, скрытие превью, запрет чужой ссылки и HTML-экранирование. Реальные запросы Telegram в тестах заменены mock-транспортом. До продаж проведите полный сценарий на отдельном боте и тестовом окружении платежей Telegram.

Документация проверена 17.11.2026 через Context7 и официальные источники:

- https://core.telegram.org/bots/api
- https://core.telegram.org/bots/payments-stars

Для цифрового доступа Telegram требует Stars/XTR. У API нет гарантированной единой частоты для любого метода: учитывайте ограничения конкретного метода, чата и ответ retry_after. У неизвестного источника рынка лимиты и поля пока не установлены.
